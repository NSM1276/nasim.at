# Nasim Vision — план платформы

Дата: 2026-09-18. Статус: архитектура согласована, код ещё не написан.
Этот файл — единственный источник правды по проекту. Любое изменение решений вносится сюда.

---

## 1. Что строим

Локальная коробка (мини-компьютер), которая подключается к уже существующим IP-камерам
ресторана, бара, отеля или магазина и ведёт аналитику посещаемости. Рынок: Вена, Австрия.

Главное обещание клиенту: **видео и данные не покидают объект.** Никакого облака,
вся обработка и хранение на коробке. Мы не заменяем систему безопасности клиента,
мы добавляем к ней аналитику.

Слоган для продаж: «Мы не видим ваших гостей. Мы видим цифры».

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Железо | Два тарифа: NVIDIA Jetson Orin NX (дорогой) и Intel-мини-ПК N100/N305, 16–32 ГБ (дешёвый). Один код, меняется только движок детекции. |
| Объём первой версии | Только посещаемость: вошли, вышли, сейчас внутри, графики по часам/дням, сравнение с прошлой неделей. Зоны и столы — позже, архитектура готова к ним. |
| Хранение видео | Не храним. Видео пишет регистратор клиента (NVR), коробка берёт тот же RTSP-поток параллельно и хранит только события и счётчики. Модуль записи в архитектуре есть, в первой версии выключен. |
| Обслуживание коробок | Служебный канал с первого дня: коробка сама раз в день спрашивает обновление и отправляет только техническое состояние. Выгрузка цифр в облако — платная опция позже, только по явному согласию клиента. |
| AI-помощник | Ночные сводки на любом железе. Чат с вопросами к данным — на Jetson. Модель за узким интерфейсом: локально Ollama по умолчанию, облачный API только по отдельной галочке с согласием клиента. Вся аналитика работает без модели. |
| Кто настраивает | Только мы, с выездом. Интерфейс настройки инженерный, не для клиента. |
| Доступ клиента к панели | С телефона из любого места через VPN-туннель (Tailscale, при росте — Headscale + WireGuard). Без облака. |
| Язык интерфейса | Немецкий и английский с переключателем (см. открытые вопросы). |

## 3. Рассмотренные подходы

**A. Frigate как основа.** Готовый open-source NVR с детекцией, поддержкой TensorRT и OpenVINO.
Плюс: зрелый приём RTSP, готовый веб-интерфейс. Минус: это регистратор, а не аналитика.
Подсчёт пересечения линий слабый, пришлось бы гнуть чужой продукт под себя и тащить
хранение видео, от которого мы отказались.

**B. Свой тонкий конвейер из готовых библиотек.** YOLO + supervision + FastAPI + SQLite.
Плюс: ровно наша задача, лёгкий, полный контроль, легко добавлять зоны и столы.
Минус: приём RTSP (переподключения, битые потоки) на нас.

**C. NVIDIA DeepStream.** Мощно, но только Jetson. Ломает решение про два тарифа. Отклонён.

**Выбран B.** Frigate остаётся кандидатом на роль необязательного модуля записи в будущем.

## 4. Стек (всё бесплатное, open source)

| Слой | Инструмент | Зачем |
|---|---|---|
| Приём видео | FFmpeg / GStreamer через OpenCV | RTSP с любых IP-камер |
| Детекция людей | YOLO nano/small (Ultralytics для прототипа, см. лицензию) | Одна модель, экспорт в TensorRT (Jetson) и OpenVINO (Intel) |
| Трекинг и подсчёт | supervision (Roboflow) + ByteTrack | Готовые LineZone и PolygonZone, ничего не пишем сами |
| Хранение | SQLite | Один файл, без сервера БД |
| Бэкенд и API | Python, FastAPI | Управляет конвейером, отдаёт данные панели |
| Панель | React + Vite + Tailwind + shadcn/ui, Recharts, i18next | Графики, настройка линий, DE/EN |
| AI-помощник | Ollama (Qwen 2.5 3B или Llama 3.2 3B) | Ночные сводки, чат на Jetson |
| Упаковка | Docker Compose | Коробка разворачивается за 10 минут |
| Удалённый доступ | Tailscale | Панель с телефона без облака |
| Обновления | Служебный агент, тянет подписанные docker-образы | Без входящих соединений на коробку |

## 5. Архитектура коробки

Модули независимы, общаются через узкие интерфейсы. Каждый можно тестировать отдельно.

```
IP-камеры (RTSP)
      │
      ▼
[1] Ingest ── кадры ──▶ [2] Detector ── боксы ──▶ [3] Tracker+Counter ── события ──▶ [4] Store (SQLite)
      │                  (TensorRT/OpenVINO)         (supervision)                          │
      └──▶ [8] Recorder (выключен в v1)                                                     │
                                                                                            ▼
                                        [5] API (FastAPI) ◀──────────────────────── читает
                                             │        │
                                             ▼        ▼
                                    [6] Web UI    [7] Assistant (Ollama | облачный API)

[9] Agent — раз в день: «жива, версия, диск, камеры онлайн» → наш сервер; тянет обновления
```

| # | Модуль | Делает | Интерфейс |
|---|---|---|---|
| 1 | Ingest | Читает RTSP, переподключается, отдаёт кадры с меткой времени | `frames(camera_id) -> итератор кадров` |
| 2 | Detector | Находит людей на кадре | `detect(frame) -> список боксов`. Реализации: TensorRT, OpenVINO, CPU-заглушка для разработки |
| 3 | Tracker+Counter | Ведёт треки, считает пересечения линий и (позже) зоны | `update(boxes) -> список событий` |
| 4 | Store | Пишет события, считает почасовые агрегаты | `write_event`, `query(...)` |
| 5 | API | REST для панели, управление камерами и линиями | HTTP/JSON |
| 6 | Web UI | Панель для клиента + инженерная настройка | Браузер |
| 7 | Assistant | Сводки и чат поверх агрегатов | `answer(question, data) -> text`. Реализации: Ollama, облачный API |
| 8 | Recorder | Клипы по событию / полная запись | Выключен в v1 |
| 9 | Agent | Здоровье коробки, обновления | Исходящий HTTPS раз в день |

## 6. Модель данных (SQLite)

- **cameras** — id, имя, RTSP-адрес, включена ли, разрешение.
- **lines** — id, camera_id, две точки в координатах кадра, направление «внутрь», имя (например «Главный вход»).
- **events** — время, camera_id, line_id, направление (in/out), track_id. Это единственные «сырые» данные.
- **hourly_stats** — час, вошли, вышли, максимум внутри. Считается из events, панель читает отсюда.
- **settings** — язык, тариф, режим помощника (local/cloud), согласие на облако.

Что **не** храним никогда: кадры, видео, лица, любые признаки конкретного человека.
track_id живёт секунды и не связывается между камерами.

«Сейчас внутри» = сумма всех «in» минус сумма всех «out» по всем линиям с полуночи,
с ночным сбросом в ноль (ресторан пустой ночью).

## 7. Приватность и GDPR

- Только счётчики и события пересечения. Не персональные данные.
- Видео не сохраняется. Кадр живёт в памяти доли секунды и выбрасывается.
- Служебный канал шлёт только: id коробки, версию, uptime, диск, температуру, статус камер, последнюю ошибку.
- Любая отправка цифр наружу (облачный помощник, облачная панель) — только по явной галочке клиента с понятным текстом.
- Панель доступна только внутри локальной сети или через VPN клиента.

## 9. Дорожная карта

**Фаза 0 — среда разработки (без камер).**
Конвейер запускается на обычном ноутбуке от видеофайла или веб-камеры, детектор на CPU.
Это позволяет писать и тестировать всё до покупки железа.

**Фаза 1 — MVP, первая версия для первого клиента.**
1. Ingest одного RTSP-потока с переподключением.
2. Detector с CPU-реализацией и абстракцией под TensorRT/OpenVINO.
3. Подсчёт пересечения одной линии, запись событий в SQLite.
4. API: камеры, линии, статистика по часам/дням.
5. Инженерная страница: кадр с камеры, рисование линии мышью, направление «внутрь».
6. Панель клиента: сейчас внутри, график за день, неделя, сравнение с прошлой неделей. DE/EN.
7. Docker Compose, запуск на Intel-мини-ПК.
8. Tailscale для доступа с телефона.
9. Служебный агент: отчёт о здоровье, проверка обновлений.

**Фаза 2 — ценность.**
- Несколько камер и линий, ночные сводки через Ollama.
- Реализация детектора под TensorRT для Jetson.
- Чат с вопросами к данным на Jetson.
- Экспорт отчётов (PDF/CSV).

**Фаза 3 — расширение.**
- Зоны (бар, касса, витрина), время нахождения, очереди.
- Столы и оборачиваемость.
- Клипы по событию / Frigate как модуль записи.
- Платная облачная панель с выгрузкой цифр по согласию.

## 10. Открытые вопросы

1. **Лицензия детектора.** Ultralytics YOLO — AGPL, для закрытого коммерческого продукта нужна платная лицензия или замена на YOLOX / RT-DETR (Apache 2.0). Прототип делаем на Ultralytics, решение до первой продажи. Интерфейс Detector это позволяет.
2. **Язык по умолчанию.** Немецкий или английский при первом запуске.
3. **Название продукта и домен** для служебного сервера обновлений.
4. **Tailscale vs Headscale.** Бесплатный тариф Tailscale ограничен по пользователям; при 20+ клиентах, вероятно, свой Headscale.
5. **Первый клиент** — ресторан или бар? Влияет на то, какие графики показать первыми.
